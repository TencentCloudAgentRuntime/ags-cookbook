# pi 1.4.0 多实例会话切换（参考实现）

[English](./README.md) · [pi 1.4.0 文件/RPC 接入](../../README_zh.md) · [Session 示例总览](../../../README_zh.md)

## 先看这里

**解决什么问题。** 你有两个常驻的 pi 服务实例（A 和 B）。同一个会话，这一轮由 A 处理，下一轮由 B 处理，再下一轮又回到 A，全程不重启、不共享磁盘、不做会话粘滞（不要求固定把某个会话路由到某个实例）。

**怎么解决。** 每个请求都从云端 Session 读出完整历史，建一个全新的内存会话，处理完就丢弃。云端 Session 是唯一的历史来源，实例本身不保存任何会话状态，所以"换实例"没有额外的步骤。

**你能得到：**

- 在完整的一轮之后，下一轮可以交给任意实例；
- 两个实例同时抢同一轮时，只有一个会执行，另一个在调用模型或工具**之前**就被拒绝（HTTP 409）；
- 模型调用失败时，这一轮会被正常收尾，会话仍然可以继续用，不需要人工处理；
- 某个实例崩溃留下没有收尾的轮次时，超过超时时间（默认 10 分钟）后会被下一个请求自动接管并收尾；
- 实例收到停止信号（部署、缩容）时，会等进行中的轮次结束，必要时中止并收尾。

**你得不到：**

- 一轮执行到一半时，换另一个实例接手继续；
- 已经执行过的工具被自动重放或撤销；
- 工作区里的文件、正在运行的进程跟着会话搬走（会话只保存对话历史）；
- 完整的 pi RPC / 终端界面。这里只有 `POST /prompt` 和 `GET /health`；
- 服务端的锁或租约。依赖的是现有的 EventId 唯一性。

**代价：** 每个请求都要冷加载完整历史，云端读取量比文件/RPC 实现高；长会话更明显（见[成本](#成本)）。

## 术语

| 词 | 含义 |
| --- | --- |
| 轮次（turn） | 一次 `POST /prompt` 对应的一整轮：用户输入、模型回答、中间可能的工具调用 |
| 占位（claim） | 每一轮开始时，先把一条 `state: open` 的边界记录写进云端，写成功了才去调用模型或工具。两个实例抢同一个位置时，云端只让一个写成功 |
| open / closed 边界 | 云端历史里的 `ags-turn-boundary` 记录。最后一条是 `open` 表示这一轮还没有结束 |
| EventId | 每个事件的唯一标识，由它在会话里的序号推出。云端对"相同 EventId、内容不同"的请求返回冲突，这是整个方案检测抢占的基础 |

## 与文件/RPC 实现的对比

对比对象是 [pi 1.4.0 文件/RPC 示例](../../README_zh.md)，不是另一个 pi 版本；两者都固定 `@earendil-works/pi-coding-agent@1.4.0`。

| 项目 | 文件/RPC 示例 | 本目录（SDK/HTTP） |
| --- | --- | --- |
| 入口 | 官方 pi 可执行文件的 RPC 模式 | 一个小的 HTTP 服务调用官方 pi SDK |
| 是否改 pi 源码 | 否 | 否，新增的只是 SDK 外层的应用代码 |
| 会话生命周期 | `SessionManager` 在内存里管理，并写本地 JSONL；进程继续用已加载的会话 | 每个请求新建 `SessionManager.inMemory` 和 Agent，结束后释放 |
| 云端恢复 | 启动时恢复；本地已有文件就跳过 | 每个请求都读云端头和历史，包括回到同一实例的请求 |
| 并发 | 需要把同一会话路由到一个实例；冲突可能让旧进程一直失败 | 执行前先写 `open` 占位，抢占失败被拒绝；之后的请求重新加载 |
| 未结束的轮次 | 没有对应的协议 | 拒绝接手，不改历史，不自动重放 |
| 模型报错 | 视情况 | 这一轮收尾为 `closed`（`outcome: "error"`），会话可继续 |
| 交互能力 | pi RPC、终端、`/fork`、`/resume` 等 | 只有 `POST /prompt` 和 `GET /health` |
| 本地状态 | 会话文件和活跃会话对象 | 模型配置和工作目录可以在本地，会话历史在云端 |

## 构建与运行

### 前置条件

- Docker；
- 已创建的 SessionSpace，以及有 Session API 权限的云凭证；
- 一个可用的模型接口；
- 本地检查需要 Node.js 24 和 npm。

> **安全提示。** 示例服务**没有身份验证**，而且默认给 agent 装备了可以执行命令的工具。只在本机或可信的鉴权网关之后运行，不要直接暴露到网络上。

### 配置

```sh
cp .env.example .env
# 填写 .env；不要把真实凭证文件复制进镜像。
```

需要填写：`AGR_REGION`、`SESSION_SPACE_ID`、`SESSION_USER_ID`、`TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`。按环境设置 `SESSION_API_ENDPOINT`；`SESSION_AGENT_ID` 和临时凭证 `TENCENTCLOUD_SESSION_TOKEN` 可选。两个实例必须使用**相同**的 Session 身份和 Agent 过滤条件。云 API 必须原样返回 `ResourceInUse.EventIdDuplicate`、`ResourceInUse.SessionIdDuplicate` 和 `ResourceNotFound.SessionNotExist`；其他错误原样向上传递，不会被回读后重新解释成冲突。

### 构建并检查

```sh
make setup   # 安装依赖
make check   # 语法检查和单元测试
make build   # 构建镜像
# ARM 宿主机：make build PLATFORM=linux/arm64
```

### 启动两个实例

在两个终端里启动同一个镜像，**不要**挂载共享的会话目录：

```sh
make run PORT=18081
make run PORT=18082
```

### 验证 A → B → A

等每个请求返回后，再用同一个 `sessionId` 访问下一个实例：

```sh
curl -sS http://127.0.0.1:18081/prompt -H 'Content-Type: application/json' \
  -d '{"sessionId":"handoff-demo","text":"Remember marker ALPHA-42. Reply only ACK."}'
curl -sS http://127.0.0.1:18082/prompt -H 'Content-Type: application/json' \
  -d '{"sessionId":"handoff-demo","text":"Reply only with the earlier marker."}'
curl -sS http://127.0.0.1:18081/prompt -H 'Content-Type: application/json' \
  -d '{"sessionId":"handoff-demo","text":"Reply only with the earlier marker."}'
```

**预期：** 回复依次是 `ACK`、`ALPHA-42`、`ALPHA-42`；响应里的 `eventCount` 逐次增加；全程没有重启任何实例。第三个请求回到 A，A 的内存里没有任何东西，是从云端重新加载的，所以仍然能答出 B 看到的内容。

`GET /health` 只表示进程活着，不代表云端和模型都可用。

### 接口与错误码

| 请求 | 响应 |
| --- | --- |
| `POST /prompt`，体为 `{"sessionId": "...", "text": "..."}` | `200`，`{"reply": "...", "eventCount": N}` |
| 请求体不是合法 JSON，或 `sessionId` / `text` 缺失、格式不对 | `400 invalid-request` |
| 上一轮没有结束且最近还有动静，或本实例已经在执行这个会话 | `409 session/agent-busy`，按 `Retry-After`（秒）稍后重试 |
| 别的实例抢先写入（同一轮、同一个新会话） | `409 ResourceInUse.EventIdDuplicate` 或 `ResourceInUse.SessionIdDuplicate`，稍后重试 |
| 本实例正在停止 | `503 session/shutting-down`，换一个实例重试 |
| 其他错误 | `500 internal-error`。详细信息只写在服务端日志里，不返回给客户端 |

`sessionId` 只允许字母、数字、`_`、`.`、`-`，且以字母或数字开头，最长 128 个字符。请求体最大 1 MiB。

## 一个请求怎么走

1. 用 `DescribeSession`、`DescribeEvents` 读出会话。新会话从空历史开始；历史不连续就拒绝。最后一轮是 `open` 时：最近还有动静就拒绝，静默超过超时就先把它收尾（见下文）。
2. 用官方 SDK 建一个全新的内存 `SessionManager` 和 Agent。
3. 追加一条 `state: open` 的边界记录，带一个随机的请求标识，**写成功后才调用模型**。随机标识让两个同时开始的请求内容不同，所以云端会把后到的那个当成冲突，而不是当成"同一个请求的重试"。
4. 执行提示词。在 `message_end`、`turn_end`、`tool_execution_end` 时依次保存检查点；保存失败时尽量中止执行。
5. 成功后追加 `state: closed` 的边界记录，返回 `reply` 和 `eventCount`，释放这次的 Agent。

占位之后，本实例在这个位置上已经是唯一的写入者（别的实例在下一个位置写会得到 EventId 冲突），所以检查点之间**不再重读整段历史**，只在请求开始时校验一次。

### 失败时会怎样

| 失败发生在 | 云端留下什么 | 之后 |
| --- | --- | --- |
| 占位之前（读历史、占位写入失败） | 没有变化 | 直接重试 |
| 占位被别的实例抢走 | 别人的 `open` | 你拿到 409。**不会**去关闭别人的轮次 |
| 占位之后，模型或工具报错，且云端写入仍正常 | 这一轮被写成 `closed`，`outcome: "error"` | 会话立刻可用，可以重试 |
| 占位之后，云端写入也失败了 | `open` 保持原样 | 超时后下一个请求会自动接管并收尾 |
| 实例被停止（SIGTERM） | 见下一节 | 见下一节 |

失败的这一轮永远不会被自动重放。是否重试由调用方决定；如果这一轮里工具已经执行过，重试会再执行一次，所以工具需要自己保证幂等。

### 停止实例时

收到 `SIGTERM` / `SIGINT` 后，实例会：

1. 关闭监听器，不再接受新连接；关闭过程中仍到达 host 的请求得到 `503 session/shutting-down`，新连接也可能被直接拒绝；
2. 等进行中的轮次自然结束，最多 `SHUTDOWN_GRACE_MS`（默认 20000 毫秒）；
3. 还没结束的，请求中止并尝试收尾，再等最多 `SHUTDOWN_ABORT_MS`（默认 5000 毫秒）；
4. 退出。仍有轮次没收尾则退出码为 1，并在日志里列出这些会话。

编排系统（Kubernetes 等）的终止宽限期要**大于**这两个值之和，否则进程会被强制杀掉，留下未结束的轮次。默认值之和是 25 秒，在 Kubernetes 默认的 30 秒终止宽限期内；如果你调大了这两个值，要同步调大 `terminationGracePeriodSeconds`。

云端写入也必须在退出窗口内完成。`SHUTDOWN_ABORT_MS` 要覆盖工具取消和待完成的 Session API 写入，不能只按模型取消耗时设置。即使取消生效，窗口耗尽也可能退出码为 1 并留下 open；确认执行器停止后，按下面流程恢复。

## 崩溃留下的未结束轮次

云端历史最后一条是 `open`，原因可能是：另一个实例**正在**执行，或者执行它的实例**崩溃**了（被强杀、OOM、缩容）。云端历史分不出来，所以本方案看**有没有动静**：

| 这一轮最后一条记录距现在 | 判定 | 处理 |
| --- | --- | --- |
| 不到超时时间 | 可能还在跑 | 拒绝，返回 `409 session/agent-busy`，并带 `Retry-After` 响应头提示还要等多久 |
| 超过超时时间 | 执行者已经崩溃 | **自动接管**：先写一条 `closed` 边界（`outcome: "abandoned"`）把它收尾，再执行当前请求 |

崩溃的轮次不需要人工处理：等过了超时时间，下一个请求会自动把它收尾并继续。

### 超时时间

默认 **10 分钟**，通过环境变量 `OPEN_TURN_TIMEOUT_MS`（毫秒）调整。设成非正数或非数字会在启动时报错，而不是悄悄用默认值。

**它必须比一个健康的轮次里最长的"无动静"时间长。** 模型调用或工具执行期间可能很久不产生新记录：设得太短，一个只是慢的轮次会被当成崩溃接管；设得太长，真正崩溃后会话要等这么久才能恢复。如果你的工具可能运行超过 10 分钟，请调大。

### 这个设计接受了什么风险

超时只是对"执行者死了"的**推断**，不是确认：

- **被误判的轮次会失败。** 旧执行者如果其实只是慢，它之后的写入会撞上接管者已经写下的 `closed` 边界（相同位置、相同 EventId），云端拒绝，这一轮以 409 失败。**云端历史不会被写坏，接管者的轮次也不会被它关掉。**
- **它已经启动的工具不会被停止。** 接管只能挡住它写日志，挡不住它已经在做的事，副作用可能与新一轮同时发生。工具仍然需要自己保证幂等。
- **依赖各实例的时钟大体一致。** 判断用的是记录里的时间戳。

本方案没有做心跳。

如果没有配置超时（只有直接用 `StatelessPiHost` 且不传 `openTurnTimeoutMs` 时才会这样），则永远不会自动接管，未结束的轮次一律拒绝。

## 验证情况

本目录的行为由单元测试覆盖（适配器与 HTTP host，不调用真实云端和模型），包括：占位失败、模型报错后收尾、被抢占时不关闭别人的轮次、超时自动接管、旧执行者被 EventId 冲突挡住、并发创建新会话、停止信号。

在真实云端和真实模型上，A → B → A、工具结果跨实例恢复、同时竞争、未结束历史拒绝这些基础场景在更早的版本上验证过。**自动接管崩溃的轮次、模型报错后收尾、停止信号处理是后来加入的，目前只有单元测试，还没有在真实环境里跑过。** 用于交付前，请在真实环境里补跑这几项。

## 已知限制

| 场景 | 现在的行为 | 你需要做什么 |
| --- | --- | --- |
| 两个实例同时抢同一轮 | 一个执行，另一个在调用模型/工具前被拒绝（409） | 客户端稍后重试 |
| 两个实例同时创建同一个新会话 | 一个成功，另一个得到 409 | 同上 |
| 模型报错 | 这一轮收尾为 `closed`（`outcome: "error"`），会话可继续 | 由调用方决定是否重试 |
| 实例被强制杀掉，正好有轮次在执行 | 留下 `open`。超时之前其他实例拒绝；超时之后自动接管并收尾 | 无需处理；等待时间由 `OPEN_TURN_TIMEOUT_MS` 决定 |
| 旧执行者其实只是慢，被超时误判 | 它的下一次写入因冲突失败；它已启动的工具不会被停止 | 工具保证幂等；把超时设得比最长的无动静时间更长 |
| 工具已经执行，但随后保存失败 | 副作用无法撤销，也不会重放 | 工具自己保证幂等 |
| 历史很长 | 每个请求冷加载完整历史 | 见"成本" |
| 混入不遵守本约定的写入者（文件/RPC 实现、外部客户端） | 不受保护，可能破坏历史 | 同一会话只让遵守本方案的实例写入 |
| 标题服务故障 | 当前保存报错，下次重试 | 见[标题同步](../../../title-sync_zh.md) |

关于保护范围：本方案依赖"所有写入者遵守同一套 EventId 与只追加约定"。它不是锁，也不是租约：判断执行者是否还活着靠的是超时推断，不是确认；会话保存的是对话历史，不包括工作区文件和运行中的进程，崩溃的工具不会被自动续跑。

## 成本

- **每个请求**：读一次会话头，再把全部事件分页读出来（约 `ceil(事件数 / 100)` 次），然后才开始执行。回到同一个实例的请求也一样，因为实例不保留会话。
- **每个检查点**：只追加新事件，不再重读整段历史。

读取量高于文件/RPC 实现，长会话更明显。降低请求量需要服务端提供版本游标或摘要，超出了本示例（不改 Session 服务）的范围。**不要把这个参考实现当成低请求成本的方案。**

## 本目录的文件

| 文件 | 作用 |
| --- | --- |
| `stateless/server.mjs` | HTTP 入口、错误码映射、停止信号处理；建 pi SDK 会话 |
| `stateless/host.js` | 一个请求的完整流程：读历史、接管崩溃的轮次、占位、保存检查点、收尾 |
| `extension/session-sync.js` | 把 pi 的条目追加到云端；校验序号与内容；保持稳定的 EventId |
| `extension/session-restore.js`、`session-client.js`、`session-codec.js` | 读取云端历史、Session API 客户端、条目与事件的转换 |
| `extension/session-titles.js` | 标题同步，见[标题同步](../../../title-sync_zh.md) |
| `extension/prepare.mjs` | 只生成模型配置，不再把历史恢复成本地会话文件 |
| `minimal/run-once.mjs` | 用同一套流程的一次性 SDK 入口，便于脚本里直接调用 |
| `dockerfiles/` | 独立的镜像和入口，始终启动 HTTP 服务 |

本目录不导入文件/RPC 目录的任何运行时文件：codec、client 和测试都是独立的一份。HTTP 服务不加载 `extension/index.js`（那是文件/RPC 的入口）。
